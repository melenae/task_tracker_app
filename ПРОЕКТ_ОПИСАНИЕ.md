## 1. ОБЩАЯ ИНФОРМАЦИЯ

### 1.1. Название проекта
**Task Track** — веб-приложение для отслеживания задач с двунаправленной синхронизацией данных через Apache Kafka.

### 1.2. Версия
**1.0.0**

### 1.3. Дата создания
**2024-2025**

### 1.4. Назначение
Веб-приложение для расширения функциональности десктопного приложения **ERP-tools** — профессионального инструмента для командной работы по внедрению ERP-систем.

### 1.5. Основные возможности
- ✅ Управление задачами (создание, редактирование, удаление)
- ✅ Управление проектами и командами
- ✅ Управление компаниями и клиентами
- ✅ Интеграция с внешними системами через Kafka
- ✅ Система ролей и прав доступа
- ✅ Комментарии к задачам
- ✅ Отслеживание статусов и приоритетов

## 2. НАЗНАЧЕНИЕ ПРОЕКТА

### 2.1. Целевая аудитория
- Проектные менеджеры
- Разработчики ERP-систем
- Аналитики
- Тестировщики
- Клиенты (заказчики)

### 2.2. Решаемые задачи
1. **Централизованное управление задачами** — единая точка для отслеживания всех задач проекта
2. **Интеграция с внешними системами** — синхронизация данных с 1С и другими ERP-системами
3. **Управление проектами** — организация работы по проектам с разделением по командам
4. **Контроль доступа** — гибкая система прав доступа на основе ролей и аккаунтов
5. **Отслеживание прогресса** — мониторинг статусов задач, приоритетов и дедлайнов

## 6. ФУНКЦИОНАЛЬНОСТЬ

### 6.1. Управление задачами (Issues)

#### 6.1.1. Создание задачи
- Создание новой задачи с указанием всех необходимых полей
- Автоматическая генерация `external_id`
- Автоматическая отправка события в Kafka (topic: `issues-events`)

#### 6.1.2. Редактирование задачи
- Изменение полей задачи

## 7. ИНТЕГРАЦИЯ С KAFKA

### 7.1. Архитектура Kafka интеграции

```
┌─────────────────────────────────────────────────────────────┐
│                    KAFKA TOPICS                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Topic: issues-events                                       │
│  ┌─────────────────────────────────────────────────────┐  │
│  │  Назначение: Django → 1C                              │  │
│  │  Producer: Django Application                        │  │
│  │  Consumer: 1C System (External)                       │  │
│  │  Events: created, updated, deleted,                  │  │
│  │          status_changed, comment_added               │  │
│  └─────────────────────────────────────────────────────┘  │
│                                                             │
│  Topic: issues-events-1c                                   │
│  ┌─────────────────────────────────────────────────────┐  │
│  │  Назначение: 1C → Django                             │  │
│  │  Producer: 1C System (External)                     │  │
│  │  Consumer: Django Application                        │  │
│  │  Events: created, updated, status_changed            │  │
│  └─────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

### 7.2. Producer (Отправка событий)

#### 7.2.1. Типы событий

| Тип события | Описание | Триггер |
|------------|----------|---------|
| `created` | Создание задачи | `post_save` signal (новый объект) |
| `updated` | Обновление задачи | `post_save` signal (существующий объект) |
| `deleted` | Удаление задачи | `post_delete` signal |
| `status_changed` | Изменение статуса | `pre_save` signal (проверка изменения статуса) |
| `comment_added` | Добавление комментария | `post_save` signal (IssueComments) |

#### 7.2.2. Формат сообщения

```json
{
  "event_type": "created",
  "issue_id": 123,
  "timestamp": "2025-01-17T10:30:00Z",
  "data": {
    "id": 123,
    "external_id": "TOtRv4tVLYiQopjJyFScOV4FcRXkMUmF",
    "name": "Название задачи",
    "content": "Описание задачи",
    "status": "new",
    "priority": "medium",
    "deadline": "2025-02-01T00:00:00Z",
    "user_id": 5,
    "user_external_id": "abc123...",
    "company_id": 10,
    "service_id": 15,
    "database_id": 20,
    "sprint_id": 3,
    "parent_id": null,
    "supervisor_id": 7,
    "applicant_type": "users",
    "applicant_id": 8,
    "applicant_external_id": "xyz789..."
  },
  "source": "django",
  "version": "1.0"
}
```

#### 7.2.3. Реализация Producer

**Класс:** `KafkaService`

**Методы:**
- `get_producer()` - получение или создание Producer
- `send_issue_event(event_type, issue_data, issue_id)` - отправка события

**Особенности:**
- Обработка ошибок подключения к Kafka
- Логирование всех операций
- Retry механизм для надежности

### 7.3. Consumer (Получение событий)

#### 7.3.1. Автоматический Consumer

**Реализация:**
- Запускается в отдельном потоке при старте приложения
- Подписан на топик `issues-events-1c`
- Работает в фоновом режиме

**Конфигурация:**
- `group_id`: `django-task-track`
- `auto_offset_reset`: `latest`
- `enable_auto_commit`: `true`
- `consumer_timeout_ms`: 3600000 (1 час)

**Обработка сообщений:**
1. Получение сообщения из Kafka
2. Парсинг headers в словарь
3. Вызов `_process_1c_message()`
4. Создание/обновление задачи через `IssuesService`

#### 7.3.2. Ручной Consumer (Manual Poll)

**Реализация:**
- Вызывается по запросу через веб-интерфейс
- Использует уникальный `group_id` для каждого запроса
- Читает все доступные сообщения

**Конфигурация:**
- `group_id`: `django-task-track-manual-{uuid}`
- `auto_offset_reset`: `earliest`
- `enable_auto_commit`: `false`
- `consumer_timeout_ms`: 10000 (10 секунд)
- `poll_timeout_ms`: 2000 (2 секунды)

**Использование:**
- Кнопка "🔄 Обновить из Kafka" на странице списка задач
- Позволяет вручную проверить наличие новых сообщений

#### 7.3.3. Обработка сообщений от 1C

**Маппинг полей:**

| Поле 1C | Поле Django | Преобразование |
|---------|------------|----------------|
| `Content` | `content` | Прямое копирование |
| `status` | `status` | Маппинг значений: "Новая" → "new", "В работе" → "in_progress" |
| `priority` | `priority` | Маппинг: "Regular" → "medium", "Low" → "low" |
| `dead_line` | `deadline` | Парсинг datetime строки |
| `user` | `users` | Поиск по `external_id` |
| `supervisor` | `supervisor` | Поиск по `external_id` |
| `applicant` | `applicant` | Поиск по `external_id` (GenericForeignKey) |

**Обработка ошибок:**
- Логирование всех операций
- Обработка отсутствующих пользователей
- Обработка дубликатов по `external_id`
- Пропуск собственных сообщений (source='django')

### 7.4. Конфигурация Kafka

#### 7.4.1. Настройки в settings.py

```python
# Kafka Configuration
KAFKA_BOOTSTRAP_SERVERS = 'localhost:9092'
KAFKA_ISSUES_TOPIC = 'issues-events'
KAFKA_ISSUES_1C_TOPIC = 'issues-events-1c'
KAFKA_CONSUMER_GROUP = 'django-task-track'

# Kafka Consumer Timeouts (в миллисекундах)
KAFKA_CONSUMER_POLL_TIMEOUT_MS = 3600000  # 1 час
KAFKA_MANUAL_POLL_TIMEOUT_MS = 10000     # 10 секунд
KAFKA_MANUAL_POLL_BATCH_TIMEOUT_MS = 2000  # 2 секунды
```

#### 7.4.2. Docker Compose конфигурация

**Сервисы:**
- **Zookeeper** (порт 2181) - координация Kafka кластера
- **Kafka** (порт 9092) - брокер сообщений
- **Kafka UI** (порт 8081) - веб-интерфейс для мониторинга

**Сеть:**
- Все сервисы в одной сети `kafka-network`
- Внутренняя связь через имена контейнеров

- Пропуск собственных сообщений (source='django')
- Использование флага `_skip_kafka_event` для предотвращения рекурсии

### 12.4. Асинхронная обработка сообщений

- Consumer работает в отдельном потоке
- Не блокирует основной поток приложения
- Автоматический перезапуск при ошибках

### 12.5. Маппинг данных от 1C

- Преобразование названий полей (Content → content)
- Маппинг значений статусов (Новая → new)
- Маппинг приоритетов (Regular → medium)
- Поиск пользователей по external_id

### 12.6. Система контроля доступа

- Роли пользователей (admin, user)
